# 린코(LYNCO) 전투 프로토타입

## 최신 영향 대상 선택·탑뷰 (2026-09-27)

- 평소 방향은 카드 가장자리 밖으로 나온 굵은 돌출 탭으로 표시합니다. 테이블 카드를 좌클릭하면 선택 카드는 유지하고, 해당 방향의 바로 인접한 카드까지 연결선·화살촉과 마젠타 글로우를 표시합니다. 다른 배치 카드는 약하게 어두워집니다. 상대 카드는 180도 회전에 맞춰 방향을 반영하고, 맞은편 복제도 같은 논리 대상을 강조합니다.
- 같은 카드를 다시 클릭하거나 빈 칸 클릭, Esc로 해제합니다. 카드 배치·턴 전환·재시작에서도 해제합니다. 상세창은 테이블 카드 **우클릭**으로 엽니다.
- MMB(휠 클릭)는 내 테이블을 수직으로 내려다보는 정사영 탑뷰입니다. 손패/HUD/주변 오브젝트/맞은편은 숨기며 카드 클릭으로 영향 대상을 확인할 수 있습니다. 휠 클릭·Esc·R로 이전 시점에 복귀합니다. 탑뷰에서 휠 위는 확대, 아래는 축소입니다. 확대 범위는 기본 화면 대비 약 0.8~2.86배이며, 창 비율 변경 시 현재 확대 비율을 유지합니다.
- 이 기능은 기존 임시 방향 데이터의 시각적 확인입니다. 실제 시너지 조건·보너스·전투 규칙을 확정하거나 발동하지 않습니다.
- Compatibility 렌더러에서 부드러운 글로우를 표시하는 별도 셰이더를 사용하며, 선택/해제에 노드나 소재를 반복 생성하지 않습니다.

## 최신 맞은편 분위기 (2026-09-27)

- 맞은편 테이블과 배치 카드는 불투명도 84%로 살짝 비칩니다. 가까운 테이블과 카드는 기존 선명도를 유지합니다.
- 두 테이블 사이에는 가장자리가 부드럽게 사라지는 어두운 구간을 넣었습니다. 화면 전체를 덮거나 깜빡이지 않습니다.
- 맞은편 전용 소재를 캐시하여 공유 텍스처를 재사용합니다. 상대 카드 호버로 밝기를 복원해도 맞은편의 투명도는 유지합니다.
- 맞은편 카드의 불투명 종이 코어와 접촉 그림자는 숨겨 앞면 투명화를 가리지 않도록 했습니다. 실제 점유·비용·점수는 기존 한 번 계산입니다.
- 아래 소유 표시의 전경 불투명도 유지 설명은 가까운 테이블 기준입니다. 맞은편은 이 항목의 투명도가 적용됩니다.

## 최신 카드 소유 표시·직선 전달 (2026-09-27)

- 내 테이블에서 내 카드는 정방향+짧은 실선, 상대 카드는 180도 방향+짧은 점선으로 구분합니다. 맞은편 복제도 동일한 소유 관계를 유지합니다.
- 상대 카드의 바탕만 살짝 어둡게 표시하며 글자·심볼·비용 요소의 스타일과 불투명도는 유지합니다. 테이블 상대 카드에 호버하면 양쪽의 해당 카드 바탕을 원래 밝기로 복원하고, 벗어나면 다시 어둡게 표시합니다. 상세창은 정방향이며 ‘내 카드 / 상대 카드’를 명시합니다.
- **맞은편에 보이는 내 카드 복제는 즉시 표시**합니다. 맞은편으로 날아가는 이동 연출은 제거했습니다.
- **상대 카드 → 내 테이블은 회전·포물선·바운스 없는 직선 삽입**입니다. 기본 0.22초 이동 + 0.04초 박자, 간결한 연출 0.10초 + 0.02초입니다. 카메라 전환과 내 손패의 기존 로컬 배치 연출은 유지합니다.
- 배경만 다른 카드 소재를 시작할 때 6종 준비해 공유합니다. 호버는 소재 참조만 바꾸며 추가 노드·Tween을 생성하지 않습니다. 실선/점선의 메시와 소재도 공유합니다.
- `tests/ownership_ui_test.gd`: 소유 표시, 배경·전경 대비, 호버 복원, 정방향 상세, 상태 불변, 직선 궤적·고정 회전, 즉시 복제, 초기화 검사. 아래 이전 ‘거울 전달 비행’ 설명보다 이 항목이 우선합니다.

## 최신 맵 — 두 테이블과 거울 전달 연출 (2026-09-27)

- 기본 카메라는 가까운 내 테이블을 크게, 맞은편 테이블을 작게 보여주는 약 80:20 구도입니다. WASD·우클릭으로 이동하면 이 비율은 달라집니다.
- 두 테이블의 가로 폭은 기존 15에서 **22.5(1.5배)**로 확대했습니다. 상판·옆면·충돌체·다리를 함께 조정했고, 육면체 4개는 넓어진 상판 외곽에 배치했습니다.
- 내 카드가 놓이면 맞은편 대응 위치에도 전달 연출과 함께 같은 카드가 보입니다. 맞은편은 **시각적 복제**이며 실제 점유는 기존 18칸, 카드·비용·점수는 한 번만 계산합니다.
- 상대 턴에는 카메라가 위쪽을 바라보며 상대 테이블과 공중 손패를 보여줍니다. 상대 손패는 포물선형 부채꼴이며, **상대 카드 뒷면은 로고 없는 검정색**입니다. 선택한 카드만 공개되어 내 테이블로 날아옵니다.
- 상대 턴이 끝나면 내 시점으로 복귀하며, 턴 전 WASD 위치와 시야 회전도 복원합니다. 전환·상대 행동 중에는 배치/손패/카메라 입력을 차단합니다. 간결한 연출에서는 이동 시간을 줄입니다.
- `TableWorld/OpponentTable`과 `OpponentHand`가 추가되었습니다. `table_view.gd`의 `mirror_cards`는 표시 전용이고 `cards`만 기존 점유 판정에 사용합니다. 상대 손패는 최대 7개의 3D 오브젝트를 재사용합니다.

검증: 실제 Godot `tests/mirror_ui_test.gd` 54항목 PASS, 8회 턴 전환·재시작 노드 200/200. 이전 모델과 256판의 카드·비용·점수·승패·난수 일치 확인. 캡처: `test-results/mirror_player_1280.png`, `mirror_opponent_1280.png`, `mirror_returned_1280.png`.



## 최신 플레이 방식 — 테이블 판정·덱 상점 (2026-09-27)

아래 이전 날짜/같은 날짜의 기록보다 이 항목이 우선합니다. 체력 전투에서 테이블 점수 대전으로 전환한 시제품입니다.

- 내 차례에 **행동력 3** 안에서 여러 카드를 사용한 뒤 턴을 종료합니다. 상대도 행동 비용을 지불하며 배치합니다. 턴 종료 시 남은 손패는 버리지만 **배치한 카드는 유지**합니다.
- 기존 **6×3 / 18칸**이 가득 차면 즉시 양쪽 테이블 코스트를 합산합니다. 높은 쪽 승리, 같은 점수는 무승부입니다. 후공의 추가 행동 보장 규칙은 없습니다.
- 카드 왼쪽 위는 **행동 비용**, 오른쪽 아래 둥근 정육각형은 **테이블 코스트**입니다. 손패·도감·테이블·확대 상세에 반영했습니다. 가려진 카드에서는 코스트도 숨깁니다.
- 현재 임시 테이블 코스트: 일격 4 / 관측 2 / 봉쇄 3 / 기억 추출 1 / 순환 1 / 연쇄 6. 골드·행동력과 독립적으로 집계합니다.
- 관측·기억 추출의 1장 드로우와 순환의 행동력 +1은 적용합니다. 옛 체력 피해·방어·관측 추가 피해를 새로운 점수/방해 효과로 임의 변환하지 않았습니다. 해당 카드의 추가 효과는 설계 대기입니다. 테이블 배치 자체의 기본 점수는 얻습니다.
- 킹·조커와 일반 뒷면은 계속 정체 공개만 합니다. 효과·행동 비용·테이블 코스트는 미정이며 적용하지 않습니다(점수 기여 0, 표시 `—`). 공개한 뒷면도 테이블에 남습니다. E·Shift 및 드로우 시연의 비용·횟수 제한은 여전히 미정인 시험 기능입니다.
- 임시 상대 **웃는 잔상**은 18장 덱을 사용합니다. 시드 기반 손패에서 비용을 감당할 수 있는 카드 중 테이블 코스트가 높은 카드를 우선 배치합니다. 실제 인접 시너지·연결 차단·방향 효과는 미구현입니다.
- 임시 골드 보상: 승리 30 / 무승부 15 / 패배 10. 판정당 한 번 지급합니다. 상점에서 **60골드**로 웃는 잔상 덱 전체를 해금한 뒤 사용 덱으로 선택할 수 있습니다. 선택한 18장 구성으로 다음 경기를 시작합니다.
- **구매는 상점에서만** 합니다. 도감의 **돋보기 ‘덱 주인’**으로 선택 카드가 포함된 덱과 주인을 확인하고 상점으로 이동할 수 있습니다.
- 골드·해금·선택 덱은 **현재 앱 실행 중에만 유지**됩니다. 앱을 종료하면 초기화되며 영구 저장/런 구조는 확정하지 않았습니다.
- **WASD**: 카메라 평행 이동. **우클릭 드래그**: 기존 제한된 시야 회전. **R**: 위치·회전 중앙 복귀. 상세창·셔플/연출·드래그·시드 입력·포커스 이탈 중에는 이동을 차단합니다. 이동 속도·범위는 TableWorld Inspector에서 조절합니다.

구조: `scripts/table_battle_model.gd`는 새 전투 규칙, `collection_session.gd`는 실행 중 골드·덱 해금, `shop_screen.gd`는 상점, `table_cost_badge.gd`는 둥근 육각형 표시입니다. 옛 `battle_model.gd`와 카드 원본 정의는 과거 동작 검증용으로 보존했고, 실제 전투는 새 모델 및 `Catalog.table_card()`를 사용합니다. 테이블 방향 데이터는 계속 시각 확인용입니다.

## E 보충·Shift 셔플·킹/조커 로고 (2026-09-27 최신)

- **E**: 남은 손패를 유지하며 5장까지 앞면으로 보충. 보충 완료 손패에는 고정된 킹·조커 뒷면 카드가 합계 최소 1장 포함됩니다.
- **Shift**: 현재 손패를 화면 중앙에 모아 동일한 가림면으로 셔플하고 무작위 위치에 재배분. 카드 구성과 장수는 유지합니다.
- 가린 카드 **한 번 클릭**: 해당 카드의 고유 뒷면 정체를 공개하고 테이블에 배치합니다. Shift 셔플 중과 가린 카드가 남아 있는 동안만 손패 묶음 좌측 상단에 전체 손패의 킹·조커 개수를 한 번 표시합니다. 수량 표시는 별도 제작한 왕관·조커 모자 SVG를 사용합니다.
- 사용자 선택에 따라 현재는 **정체 공개까지만 구현**했습니다. 일반 뒷면·킹·조커의 미정 효과와 비용은 적용하지 않습니다. 공개 후 버림패로 이동합니다.
- 임시 확인용 배정: **봉쇄→킹 / 기억 추출→조커**. 최종 능력·분포 확정이 아닙니다. E·Shift 비용·횟수 제한도 아직 시험 상태입니다.
- 흰 카드에는 제공된 검정 킹·조커 PNG, 검정 카드에는 제공된 흰 PNG를 사용합니다. 가림 카드 자체에는 정체 심볼을 노출하지 않습니다. 수량용 공통 아이콘은 개별 카드 위치와 관계없이 전체 합계만 나타냅니다.
- 기존 앞면 전투·드로우 연출·호버·시야·상세창은 유지합니다. E의 목표는 5장이며 기존 추가 드로우의 임시 최대 7장은 유지합니다.

상세 규칙·미정 사항·재현 명령: [카드_드로우_구현현황.md](카드_드로우_구현현황.md).

## 메인 화면과 카드북 (2026-09-26 최신)

프로젝트 실행(F5 / run.cmd)은 `scenes/main_menu.tscn`에서 시작합니다. **게임 시작 → 기존 전투**, **수집 카드북 → 기존 카드 6종 열람**, **종료**를 사용할 수 있습니다. 카드북은 메인 버튼 또는 Esc, 전투는 왼쪽 위 메인 버튼으로 돌아갑니다. 현재 전투 진행은 저장하지 않습니다.

카드북은 `catalog.gd`와 기존 카드 렌더러를 재사용합니다. 흑백 카드의 비용·분류·심볼·전체 효과를 확인할 수 있으며 수집 해금·영구 저장은 아직 구현하지 않았습니다. 새 화면은 밝은 배경, 흑백·회색 정보 위계, 둥근 카드와 선택을 나타내는 노란 테두리를 사용합니다.

전투의 3D 씬·규칙·카드 배치·드로우·호버·시야·상세창은 유지했습니다. 체력·행동력·적 의도의 새 배치는 **시안만 준비했으며 실제 전투에는 적용하지 않았습니다**. 배치와 캡처는 [UI_화면_구성안.md](UI_화면_구성안.md)를 확인합니다.

- 행동 불가 사유와 선택 카드의 효과 표시
- 연출 중 입력 차단, 중복 사용 방지, 카드 수 보존 검증

### 테스트용 임시 규칙

규칙은 `scripts/catalog.gd`에서 관리합니다. 이 수치들은 최종 설계 확정이 아닙니다.

- 캐릭터 체력 40, 적 체력 64

- 방어는 적의 공격을 막고 다음 턴에 소멸
- 기억 추출과 순환은 사용 후 전투 내 소멸
- 적 공격은 6 / 9 / 12 / 7 순서로 반복 (현재 상단 적 정보 UI는 제거됨)

## 구조와 성능

- `scripts/battle_model.gd`: UI에 의존하지 않는 전투 상태와 규칙
- `scripts/catalog.gd`: 카드·캐릭터·적 데이터, 확장용 특전 목록
- `scripts/battle_ui.gd`: 화면, 입력, 애니메이션과 결과 표시
- `scripts/card_view.gd`: 카드의 둥근 배경, 글자, 아이콘, 호버/선택
- `scripts/meter.gd`, `scripts/board.gd`: 변경 시만 다시 그리는 단순 2D 표시
- `assets/icons`: 제공 이미지에서 분리한 실제 PNG 7장만 사용. 전체 718장을 로드하지 않습니다.

Compatibility 렌더러, VSync, 최대 120FPS를 사용합니다. 3D 테이블에는 실시간 조명과 카드 그림자를 사용합니다. 물리 낙하 시뮬레이션과 매 프레임 파일 접근은 없습니다. 아이콘, 카드 텍스처와 메시·재질을 공유합니다. 카드 이동은 각 단계의 Tween에 짧은 간격으로 예약하며, 평상시 게임 UI의 `_process`는 비활성입니다. 성능 측정 중에만 프레임 샘플을 기록합니다.

카드 효과 처리 순서는 **검증 → 비용 차감 및 손패 제거 → 버림/소멸 분류 → 기본 효과 → 연계 추가 효과 → 승리 확인 → 추가 드로우**입니다. 빈 덱에서 드로우할 때만 버림패를 시드 기반으로 섞습니다.

같은 해상도에서도 GPU, 드라이버, 백그라운드 작업에 따라 프레임은 달라질 수 있습니다. 실제 측정값과 검증 범위는 `test-results/renderer_test.json` 및 `검증결과.md`에서 확인합니다. Godot의 엔진 프레임 시간에는 동기화 대기가 포함될 수 있으며, 순수 게임 로직 CPU 사용 시간과 같지 않습니다.
